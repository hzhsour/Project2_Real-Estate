## Adaptation record

- `src/sprint6_q2_model.py` adapts the Stage 1 design construction and Stage 3 centred fitting logic, while reusing the existing causal rental feature builder and the existing project-specific Theta approximation and Drift implementations. It rebuilds the 12-quarter and 20-quarter growth targets separately, keeps one common complete 145-market population, applies chronological expanding-cohort training and the analyst-imposed one-quarter label-maturity embargo, fits `StandardScaler` only inside the training pipeline, centres training outcomes within origin cohorts, and re-centres fitted residual predictions before adding the horizon-specific macro anchor.
- Ridge21 uses the frozen 21-feature set and alpha 100 with the project-specific 50:50 OLS/SES Theta approximation anchor. Ridge18 uses the frozen 18-feature set (Ridge21 minus the three behaviour features) and alpha 100 with the full-history Drift anchor. The project-specific Theta approximation is not described as canonical Theta.
- The model module exposes in-memory current-candidate reproduction and matched historical validation. It contains no writer for registered forecasts or ledger entries. The notebook continues to present the frozen forecasts; it does not refit either model during ordinary display.
- `src/sprint6_q2_registry.py` adapts the Stage 7 integrity requirements into a reusable read-only package loader. It additionally rejects paths outside the package directory and raises on digest, schema, identity, arithmetic, rank or provenance inconsistencies.
- Project-local changes are limited to removing private absolute research paths, using repository-relative inputs, making missing schema/duplicate keys fail explicitly, exposing reusable in-memory functions, and separating package integrity validation from model fitting. No additional dependency was installed.

## Verification and limits

Metric-unit clarification (17 October 2026): `_top_k_recovery` returns the expected recovered market **count**, the dot product of actual and predicted fractional Top-K memberships. The historical runner now exports `tie_aware_top10_recovery_count` and, separately, `tie_aware_top10_recovery_fraction` (count divided by `min(10, population)`). The former ambiguous `tie_aware_top10_recovery` field held a fraction; the only project caller was updated and no other local consumers were found. Published historical Top-10 hits remain counts out of ten. This later source correction does not amend frozen forecasts, provenance JSONs, ledgers or historical validation receipts.

Using the existing local processed long-history input, both current candidates were refit in memory and compared market-by-market with the frozen registered CSVs. Maximum absolute cumulative-growth differences were `8.9e-15` percentage points for Ridge21 and `2.2e-14` for Ridge18, well inside the `1e-9` tolerance; all other numeric forecast fields, feature-domain warning lists and Top-10 market vectors also matched. The 2010–2020 historical runner was separately compared with the saved Stage 5 matched-prediction evidence: each candidate matched all 1,595 market-origin predictions, with maximum differences of `1.1e-14` pp (Ridge21) and `6.1e-14` pp (Ridge18). These are implementation-reproduction checks, not new evidence of future accuracy. The forecast CSVs and provenance were read-only during these checks. Their original SHA-256 values are asserted by the source-level tests.

The implementation depends on NumPy, pandas, scikit-learn and `threadpoolctl` (provided with the existing scikit-learn runtime), plus `data/processed/sprint5/long_history_validation/homes_victoria_long_history_all_properties.csv`. A clean GitHub clone may not contain this processed input or the separately generated registered-results package. Loading a frozen CSV is therefore distinct from reproducing a model fit. The historical runner is retrospective and descriptive; it does not provide independent prospective validation, deployment approval, or a guarantee of future accuracy.
